# Security Scanning with Grype

TraceLens uses [Grype](https://github.com/anchore/grype) for automated vulnerability scanning of all npm dependencies and Docker images. SBOMs are auto-generated at scan time using [Syft](https://github.com/anchore/syft) — no stale pre-committed SBOM needed.

## What runs and when

| Trigger | Scan target | Fails build? |
|---|---|---|
| Push / PR touching any `package.json`, `Dockerfile`, or the workflow file | SBOM (auto-generated by Syft from `package-lock.json`) | **Yes** — on `high` or `critical` CVE |
| Push / PR touching any `package.json`, `Dockerfile`, or the workflow file | `tracelens-api:ci` Docker image | No — advisory only |
| Push / PR touching any `package.json`, `Dockerfile`, or the workflow file | `tracelens-frontend:ci` Docker image | No — advisory only |
| Every Sunday midnight UTC | All of the above | No — advisory only (to avoid blocking unattended weekly runs) |
| Manual (`workflow_dispatch`) | All of the above | Configurable via `severity_cutoff` input (default: `high`) |

SARIF results are uploaded to GitHub's **Security → Code Scanning** tab. A JSON report is saved as a workflow artifact for 30 days.

## Workflow structure

The workflow has two jobs:

1. **`generate-sbom`** — uses `anchore/sbom-action` (Syft) to generate a CycloneDX SBOM from the live repo at CI time, uploads it as a job artifact.
2. **`scan`** — downloads the SBOM and runs three Grype scans:
   - **SARIF** output → uploaded to GitHub Code Scanning.
   - **Table** output → visible in the job log; fails the build (on non-schedule triggers) if any `high` or `critical` CVE is found.
   - **JSON** output → saved as a downloadable artifact.
   - **Docker image scans** → builds `packages/api/Dockerfile` and `packages/frontend/Dockerfile` as `tracelens-api:ci` / `tracelens-frontend:ci` and scans each; advisory only (base-image CVEs are outside project control).

## Run Grype locally

### Install

```bash
# macOS
brew install anchore/grype/grype

# Install Syft (SBOM generator) alongside it
brew install anchore/syft/syft

# Linux / CI
curl -sSfL https://raw.githubusercontent.com/anchore/grype/main/install.sh | sh -s -- -b /usr/local/bin
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh | sh -s -- -b /usr/local/bin
```

### Generate a fresh SBOM and scan it (recommended)

```bash
# Generate SBOM with Syft (mirrors what CI does)
syft . -o cyclonedx-json > sbom-generated.json

# Scan the generated SBOM
grype sbom:sbom-generated.json
```

### Scan the static SBOM (fastest — uses the pre-built `sbom.json`)

```bash
grype sbom:sbom.json
```

### Scan the live repo directory

```bash
grype dir:.
```

### Scan Docker images locally

```bash
# Build images first
docker build -t tracelens-api:local -f packages/api/Dockerfile .
docker build -t tracelens-frontend:local -f packages/frontend/Dockerfile .

# Scan each image
grype tracelens-api:local
grype tracelens-frontend:local
```

### Filter by severity

```bash
# Show only high and critical
grype sbom:sbom.json --fail-on high

# Output as JSON for tooling
grype sbom:sbom.json -o json > grype-report.json

# Output as SARIF for IDE integration
grype sbom:sbom.json -o sarif > grype-results.sarif
```

## Interpreting results

Each finding shows:

| Column | Meaning |
|---|---|
| `NAME` | Package name |
| `INSTALLED` | Version currently in use |
| `FIXED-IN` | Version that resolves the CVE (if available) |
| `TYPE` | Package type (`npm`) |
| `VULNERABILITY` | CVE / GHSA identifier |
| `SEVERITY` | `Negligible` / `Low` / `Medium` / `High` / `Critical` |

## SBOM notes

The static `sbom.json` in the repo root is kept for local/offline use. In CI, a fresh SBOM is always generated by Syft from the current `package-lock.json` so scan results are never stale due to a forgotten SBOM regeneration.

After bumping a dependency, you can update the static `sbom.json` with:

```bash
syft . -o cyclonedx-json > sbom.json
```

## Severity threshold policy

The default policy fails CI (on push/PR triggers) on `high` or `critical` findings. Scheduled weekly runs are advisory only. To override for a single manual run, set the `severity_cutoff` input in `workflow_dispatch`. To permanently change the threshold, edit the `severity-cutoff` field in `.github/workflows/grype-scan.yml`.
